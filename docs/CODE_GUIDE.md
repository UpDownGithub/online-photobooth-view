# 공개 코드 안내

실제 프로젝트의 코드에서 사용자 화면과 계산 로직을 선별했습니다. 아래 폴더는 공개한 코드의 탐색 구조이며, 서비스 전체의 구조도는 아닙니다.

## 프런트엔드

- `frontend/src/pages/room.view.js`, `review.view.js`: 촬영·결과 화면의 HTML 생성, 상태별 표시, 공통 프레임 카드 재사용.
- `pages/layouts.js`, `room.helpers.js`: 레이아웃 선택, 슬롯 좌표, 확대 초점, 스티커 좌표와 안내 문구 계산.
- `store/room.store.js`: 화면에서 사용하는 상태와 결과 미리보기 상태 전환.
- `ui/`: 아이콘, 모달, 토스트. `modal.js`의 본문 HTML은 신뢰할 수 있는 마크업 또는 이스케이프한 값으로 구성해야 합니다.
- `frontend/styles/`: 반응형 촬영·결과 화면, 디자인 토큰과 공통 스타일.
- `frontend/frames/`, `stickers/`: 화면에 사용하는 기본 이미지 자산.

화면 렌더링·상태·순수 계산·UI·CSS는 원본 로직을 유지하되 기존 주석을 정리했습니다. 공개용 경로와 의존성을 바꾼 부분은 다음과 같습니다.

| 파일 | 공개용 변경 |
| --- | --- |
| `landing.view.js` | 시작 화면 마크업과 버튼 진행 표시를 발췌. 초대 여부는 인자로 받으며 화면 외 연결 처리는 제외 |
| `room.view.js` | 이미지 주소 앞에 운영 서버 주소를 붙이지 않고 전달받은 경로를 사용. 문자열 이미지 경로는 이스케이프 |
| `room.view.js`, `review.view.js` | 카메라 상태 조회를 `ui/media-state.js`로 변경 |
| `ui/media-state.js` | 공개본을 위해 만든 표시 상태 어댑터. 카메라·네트워크 접근 없음 |
| `partial-updates.js` | 실제 부분 갱신 함수 발췌. 사용자 식별자는 인자로 받으며 설정 패널 연결 호출은 생략 |
| `sticker.interactions.js` | 실제 포인터 조작 코드 발췌. 위치 확정·삭제 결과는 `onChange`·`onRemove` 콜백으로 전달 |

이 샘플의 식별자와 화면 상태는 렌더링 입력입니다. 영상 연결과 서비스 동기화를 제공하는 코드는 포함하지 않습니다. 코드를 응용할 때는 텍스트·이미지 경로·스타일 값 등 외부 입력을 적절히 검증해야 합니다.

## 서버

프레임 목록 하나를 예시로 책임 분리를 보여줍니다.

`frame.controller.cjs` → `frame.service.cjs` → `layouts.cjs`

- 컨트롤러: 응답 형식을 만들고 목록 생성을 서비스에 위임합니다. 실제 목록 처리 함수를 발췌했습니다.
- 서비스: 기본 메모리 레지스트리에서 표시 가능한 항목을 고릅니다. 실제 응답 변환 흐름을 바탕으로 공개할 필드만 명시 선택하도록 단순화했습니다.
- 레이아웃: 프레임 규격·디자인 선택과 슬롯 좌표 계산을 담당하는 실제 순수 모듈입니다.
- 필터: 행렬 연산으로 색 변환을 구성하고, 화면에 필요한 필터 목록을 만드는 실제 순수 모듈입니다.

서버 예시는 운영 서버에 연결되지 않습니다. 영속 계층·서비스 설정·배포 진입점은 포함하지 않았습니다. 이 예시의 폴더 구성과 CommonJS 확장자는 독립적인 코드 열람을 위해 정리한 것입니다.

## 읽는 순서

1. `landing.view.js`에서 시작 화면 구성 확인
2. `layouts.js`와 `room.view.js`에서 좌표 계산과 표시의 분리 확인
3. `partial-updates.js`에서 영상 엘리먼트를 교체하지 않는 상태 갱신 확인
4. `sticker.interactions.js`에서 포인터 이동과 정규화 좌표의 연결 확인
5. 서버 예시에서 컨트롤러·서비스·순수 계산의 책임 분리 확인
